# 1. 最终选择的改进策略

## 1.1 用户视角结论

用户不关心 App 有多少模块，只关心四个问题：

```text
象限：我现在应该做什么？
专注：我什么时候做，怎样真正做下去？
成长：我使用后有没有真的变好？
我的：怎样让系统更适合我，并保证数据安全？
```

当前最容易出现的用户问题：

1. 象限页虽然功能完整，但顶部如果继续出现成长物、轻量状态、推荐、继续任务、待判断和统计，会重新变得拥挤。
2. “种子 0/3”缺少单位和行为含义，用户不知道 3 是什么，也容易因看到 0 产生压力。
3. “今天轻一点”作为长期可见功能入口，会和主行动竞争；用户也不清楚开启后究竟改变什么。
4. 专注页如果只是计时器，不能帮助用户解决“今天什么时候做”和“到时间如何开始”。
5. 成长页如果只是成长值、等级和最近奖励，无法证明用户是否更早开始、是否减少救火。
6. 我的页面如果只是杂项列表，设置难找、功能重复、数据安全感不足。
7. 当前自动化基线可靠，但没有真实设备与首次用户证据，不能把“测试通过”当成“体验已经优秀”。

## 1.2 开发者视角结论

从开发成本、数据一致性和回归风险看，最佳方案必须满足：

1. 不增加第五个“今日 / 自律”主导航。
2. 不把完整日历或完整时间线塞入象限页。
3. 不创建第二套 Task Repository、Focus Runtime、Reminder Scheduler、Score Ledger 或 Backup Storage。
4. 专注时段必须与现有 `nextStartAt`、长期任务推进计划、FocusSession、提醒预算合并展示，而不是生成三个互相冲突的日程源。
5. 成长指标必须来自真实任务、专注和修复记录；样本不足时不显示结论，不能伪造改善。
6. 页面重构优先使用现有组合根和状态源，不为本轮引入新的导航框架或大型 UI 框架。
7. 所有新增持久化模型必须版本化、迁移、备份、校验、幂等。
8. 强应用阻断、VPN、Accessibility Service、桌面小组件、云同步、完整日历和社交不属于本轮 MUST。

## 1.3 方案取舍矩阵

| 方案 | 用户价值 | 开发风险 | 页面复杂度 | 决策 |
|---|---:|---:|---:|---|
| 继续往象限页增加自律时间、成长和统计 | 中 | 中 | 极高 | 拒绝 |
| 增加第五个“今日 / 自律”主页面 | 中 | 高 | 高 | 拒绝 |
| 把现有四页重新分工，象限做减法，专注/成长/我的补足 | 极高 | 中低 | 低 | 采用 |
| 立即开发强制应用阻断 | 中高 | 极高 | 中 | 延后 |
| 立即开发完整日历、云同步、社区和游戏系统 | 中 | 极高 | 极高 | 延后 |
| 先做页面职责、专注时段、语义成长和软保护 | 极高 | 可控 | 低 | 采用 |

## 1.4 最终产品定位

对外定位：

> “先做 5 分钟”是一款面向拖延用户的任务启动与专注执行 App。四象限帮助用户选出现在最值得做的事，专注时段帮助用户在正确时间开始，第一小步降低启动压力，成长反馈让用户看见自己正在越来越早行动。

内部产品边界：

```text
象限负责选择。
专注负责安排与执行。
成长负责证明改善。
我的负责规则、保护和数据。
```

本轮成功不是“增加多少页面和字段”，而是：

```text
象限页更轻。
专注页更有执行力。
成长页更有意义。
我的页面更清楚。
用户不学习产品术语也会使用。
```

# 3. 全局页面职责与唯一归属

| 能力 | 唯一主要归属 | 其他页面如何出现 |
|---|---|---|
| 判断现在做什么 | 象限 | 专注页只显示已解析出的当前任务 |
| 添加、搜索、判断、编辑任务 | 象限 | 通知/分享可直达相同编辑器 |
| 创建专注时段 | 专注 | 我的只保存默认值，不重复创建 |
| 立即开始当前任务 | 象限、专注 | 通知可直达；只能复用同一开始服务 |
| 今日执行安排 | 专注 | 象限只显示唯一主行动 |
| 专注历史 | 专注 | 成长页只显示聚合结果 |
| 成长物和成长阶段 | 成长 | 象限不再显示“种子 0/3” |
| 今日/本周改善 | 成长 | 象限不显示统计卡 |
| 连续主动开始 | 成长 | 象限最多显示“今天已经开始过了”状态句 |
| 今天状态较差的帮助 | 任务支持流程 / 专注 | 象限只显示上下文结果，不显示永久模式按钮 |
| 默认专注时长和默认保护 | 我的 | 专注页可覆盖本次设置 |
| 提醒权限、通知预算、保护设置 | 我的 | 专注页只调整当前时段 |
| 主题、动态、屏幕阅读器优化 | 我的 | 各页读取统一偏好 |
| 备份、恢复、导出、删除 | 我的 | 其他页面不放入口 |

任何新功能必须先确定唯一主要归属。不得因为“方便入口”在四个页面各放一份完整卡片。

# 4. 全局用户体验与视觉规则

## UX-G01 每页只有一个核心问题

```text
象限：现在做什么？
专注：什么时候做，怎样做下去？
成长：有没有变好？
我的：如何配置和保护？
```

页面上与核心问题无关的内容必须降级、折叠或移动。

## UX-G02 首屏只有一个最高视觉等级主行动

- 每个页面首屏最多 1 个填充型主按钮。
- 次操作使用描边、文本或图标按钮。
- 活动专注 > 继续任务 > 当前推荐 > 新建任务，仍沿用现有 HomePrimaryAction 优先级。
- 不允许“继续专注”和“做 5 分钟”同时作为两个满宽主按钮。

## UX-G03 不显示无单位、无行为含义的比值

禁止：

```text
种子 0/3
成长 2/5
今日 0/1
积分 45
```

允许：

```text
小种子 · 距离发芽还差 15 成长值
本周已经主动开始 1 次重要任务
今天已经开始过了 ✓
获得 45 成长值
```

## UX-G04 模式名称对用户尽量隐形

内部可保留 `LowEnergyMode`、`RescueMode`、`ActionPointer`。用户界面只表达当前动作：

```text
今天轻一点        → 今天只推进一小步
低状态模式已开启  → 不显示模式状态名
最低可交付版本    → 先做能交的版本
行动指针          → 现在先做
成长洞察          → 给你的一个建议
专注复盘          → 这几分钟推进得怎么样？
```

## UX-G05 一屏不做“卡片墙”

- 每页最多 1 个大面积 Hero 卡片。
- 其他区块优先用留白、分组标题、细分隔线和普通列表行。
- 禁止每个数据、按钮和设置都包一层带阴影卡片。
- 禁止卡片内再嵌套卡片。

## UX-G06 自动行为必须解释

任何自动选择、自动上移、自动推荐、时段自动选任务都必须给出最多两条可理解原因；用户可以换一个或调整规则。

## UX-G07 所有手势都有可见替代

- 长按拖动换象限必须保留“移动到”按钮。
- 滑动完成必须有完成按钮。
- Bottom Sheet 的拖动展开必须有“编辑更多”。
- 屏幕阅读器用户无需使用拖动即可完成全部核心操作。

## UX-G08 先保存真实数据，再做视觉反馈

动画失败不得影响任务、专注、提醒和成长账本。保存失败不得关闭面板或清空输入。

## UX-G09 视觉设计 Token

先检查现有 Theme；扩展现有 Token，不创建两套主题。

建议浅色 Token：

```ts
background: '#F7F9F8'
surface: '#FFFFFF'
surfaceMuted: '#EEF4F2'
primary: '#1F7A6B'
primaryPressed: '#176255'
onPrimary: '#FFFFFF'
accent: '#E6B44C'
textPrimary: '#1D2724'
textSecondary: '#65706C'
divider: '#DCE5E1'
danger: '#C45F4A'
success: '#2B7D63'
```

象限语义色：

```ts
fire: {background: '#FCEDEA', accent: '#C76552'}

```

深色模式必须使用独立语义 Token，不得简单反色。对比度至少满足 WCAG AA：

```text
普通文字 ≥ 4.5:1
大文字和关键图标 ≥ 3:1
```

## UX-G10 字体与间距



## UX-G11 动画

```text
普通状态变化：180-240ms
Bottom Sheet：220-300ms
完成成长反馈：700-1000ms
持续呼吸：仅推荐节点，周期 ≥1800ms
```

开启减少动态后：

- 不飞行；
- 不呼吸；
- 不持续缩放；
- 使用淡入、文字与无障碍公告替代。

## UX-G12 页面状态必须完整

每个主页面必须具备：

```text
loading
ready
empty
partial-data
recoverable-error
fatal-error
```

错误文案必须说明数据是否安全和下一步操作。

## 6.2 P15R 全局原则

```text
R1  直接操控优先：能拖动就不要再弹“移动到哪里”。
R2  当前动作优先：添加面板突出添加；编辑面板突出开始。
R3  低频能力收纳：复制、长期计划、移动、删除进入“更多”。
R4  Sheet 是临时专注上下文：打开时底部主导航不可见且不可点击。
R5  关闭必须可预测：拖动、遮罩、关闭按钮、系统返回使用同一退出管线。
R6  用户输入不丢失：空标题不创建；有标题退出时安全保存一次。
R7  用户界面不显示内部模型：不显示 score、manual、hybrid、runtime、ledger。
R8  完成是独立业务事务：进度 100% 不与“完成任务”并存为两个入口。
R9  地图标签表达内容，但地图仍保持紧凑。
R10 自动化不能替代真机：拖动、键盘、Sheet、TalkBack 必须 DEVICE/UTEST。
```

## P15R-04 象限地图真正长按拖动

```text
P: MUST
USER: 用户期望“拿起任务拖到另一区域”，当前却要二次选择象限，既慢又失去空间感。
OUTCOME: 普通触摸用户直接拖动；无障碍用户仍有按钮替代。
```

### ENTRY

象限地图中的真实任务节点；聚合节点 `+N` 除外。

### FLOW

```text
单击节点
→ 打开快速编辑

长按约 300–350ms
→ 节点抬起并放大
→ 完整任务标题浮层出现
→ 节点跟随手指
→ 目标象限高亮
→ 跨轴可轻震一次
→ 松手保存最终坐标一次
→ Snackbar：“已移动到成长区 · 撤销”
```

### RULE

1. 普通长按不得再弹“移动到哪个象限”框。
2. 复用现有手势依赖；若没有 Reanimated/Gesture Handler，优先使用现有 `PanResponder`，不要为此引入大型框架。
3. 长按阈值默认 320ms，可在 300–350ms 范围按现有体验调整。
4. 进入拖动态前，移动小于 6dp 不触发位置写入；长按但未移动直接回原状态，不弹框。
5. 拖动时：
   - 节点缩放约 1.05–1.08；
   - zIndex 提升；
   - 原位置保留弱占位或阴影；
   - 显示完整标题 callout；
   - 当前目标象限使用低透明强调，不用大面积纯白。
6. 坐标转换必须复用 P8 连续重要度/紧急度领域函数。不得组件自行复制象限算法。
7. 在同一象限内松手也更新真实连续坐标；跨象限则同时更新兼容象限字段。
8. 拖动过程中只更新视觉状态和目标象限，不写 Repository、不重排全列表。
9. 松手后只写一次；使用现有 update/lifecycle service 和 operation ledger。
10. 松手在地图边界外：取消并回原位置，不保存。
11. 保存失败：动画回原位置，说明“没有移动成功，请重试”。
12. 保存成功：地图和清单立即同步，提醒协调，5 秒撤销。
13. 撤销恢复原连续坐标、象限、排序和提醒。
14. 防冲突：
    - 拖动完成后不得再触发 `onPress` 打开编辑；
    - 点击不得误触拖动；
    - 拖动时禁用 Sheet 打开；
    - 聚合节点不可拖动。
15. Haptic 只有项目已有能力时使用；同一次拖动跨入新象限时最多一次，不反复震动。
16. 无障碍替代必须保留：

```text
编辑更多 → 移动到其他象限
```

或 TalkBack 自定义 action；但普通长按不得进入该选择界面。

### DATA

- 读取当前 `importanceScore`、`manualUrgencyScore` 和 `urgencyMode`。
- 屏幕点转分数后 clamp 到 0–100；同步 legacy quadrant/important/urgent。
- 使用同一事务写入，不允许视觉位置和任务象限分开保存。

### METRIC

```text
真机 20 次拖动成功率：≥95%
快速轻点误触拖动率：≤5%
拖动后误打开编辑率：≤5%
每次拖动 Repository 写入次数：1
保存失败后错误位置残留：0
```

### AC

- [ ] 普通长按不出现象限选择框。
- [ ] 节点真实跟随手指。
- [ ] 跨轴有目标区域反馈。
- [ ] 同象限和跨象限均保存连续坐标。
- [ ] 松手只写一次。
- [ ] TalkBack 有等价移动方式。

### TEST

- 长按移动走 drag 分支，不渲染选择框。
- 拖动结束后 `update` 仅调用一次。
- `onPress` 在拖动后不触发。
- 越界释放不保存。
- 失败恢复原坐标。
- 撤销恢复全部状态。
- 无障碍移动入口仍可用。

### NO

- 不用“长按 → 弹框 → 再点象限”代替拖动。
- 不在每帧写数据库。
- 不新增第二套象限转换函数。

```text

普通
```

## P15R-06 象限首页重复入口、顶部密度与 Safe Area


### AC

```ts
  enabled: boolean;
  target: FocusScheduleTarget;
  durationMinutes: 2 | 5 | 15 | 25 | 50;
  recurrence: FocusScheduleRecurrence;
  protectionLevel: FocusProtectionLevel;

  updatedAt: string;
}

type FocusScheduleEventType =
  | 'STARTED'
  | 'SKIPPED'
  | 'RESCHEDULED'

```

RULE：

1. 不预生成无限 occurrence；按需计算未来实例。
2. 只持久化 Schedule 和已发生/例外 Event。
3. 业务键：

```text
focus-schedule-event:{scheduleId}:{localDateKey}:{type}
```

9. Schema 版本必须升级；旧数据无专注时段时安全默认空数组。

## P17-01 FocusContextSnapshot

```text
P: MUST
USER: 用户希望知道时间花在成长区还是救火区；只用任务当前象限回算历史会不准确。
OUTCOME: 从本版本起，每次专注保存开始时的任务语义快照。
```

建议：

```ts
interface FocusContextSnapshot {
  taskId: string;
  quadrantAtStart: QuadrantKey;
  importanceScoreAtStart?: number;
  effectiveUrgencyAtStart?: number;
  dueAtAtStart?: string;
  firstStepIdAtStart?: string;
  focusScheduleId?: string;
}
```

RULE：

1. 新 FocusSession 创建时捕获一次；后续任务移动不修改历史快照。
2. 旧 session 允许 `snapshot` 缺失。
3. 聚合结果标记数据质量：

```ts
type MetricQuality = 'EXACT' | 'ESTIMATED' | 'INSUFFICIENT';
```

4. 缺失快照时可用当前任务状态做 `ESTIMATED`，但 UI 不显示精确比较；重要周趋势必须 `EXACT` 或样本充分。
5. 纳入存储版本、备份、恢复和校验。

## P17-02 成长语义指标

```text
P: MUST
USER: “累计分数”无法说明 App 是否帮助用户更早开始。
OUTCOME: 成长页只展示与行动启动、重要任务和恢复有关的少量指标。
```

定义：

```ts
qualifyingFocusSession:
  actualActiveSeconds >= 120
  AND bound task exists at session start

activeStartDay:
  local day has >=1 qualifying focus session on an important task

proactiveTaskStart:
  task's first qualifying focus occurs while quadrantAtStart == GROWTH
  OR dueAtAtStart - firstStartAt >= 24h

growthMinutes:
  qualifying focus minutes where quadrantAtStart == GROWTH

repairRecovery:
  qualifying focus starts within 24h after a repair record for same task
```

每日核心：

```text
今日投入分钟
主动开始次数
成长区投入分钟
```

本周候选：

```text
重要任务提前开始数
成长区投入分钟
卡住后重新开始数
按计划开始率
```

每周只选数据质量最高、最有价值的 3 项。

关于“救火区比上周少”：

```text
仅当存在可靠的历史象限快照/事件时显示。
否则显示当前救火区任务数，不做虚假周同比。
```

RULE：

1. 不统计小于 2 分钟的误触 session。
2. 同一 task 的首次开始只计一次。
3. 聚合按用户本地日期和周起始偏好。
4. 时区变化不能重复计数。
5. 计算失败只隐藏指标，不阻断页面。

TEST：2 分钟边界、首次去重、跨午夜、时区、旧数据质量。

# 11. 单一真源、Schema 与兼容规则

## 10.1 单一真源

```text

Focus schedule：P16 新增的唯一重复专注时段源

Score/Growth：现有 operation ledger / growth domain
Reminder：现有 reminderScheduling / native module
Backup：现有 localBackupService / validation / journal
Preferences：现有 versioned preferences 扩展
```

## 10.2 迁移

所有新增字段：

- Optional-first；
- 升级 Schema 版本；
- 旧数据默认安全值；
- 单条坏记录隔离；
- 旧备份恢复后迁移；
- 新备份包含新增数据；
- 迁移失败不覆盖原快照。

## 10.3 幂等

至少使用：

```text
focus-schedule-start:{scheduleId}:{localDateKey}
focus-schedule-event:{scheduleId}:{localDateKey}:{type}
task-first-start:{taskId}
task-first-step:{taskId}
task-completion:{taskId}
focus-completion:{focusSessionId}
```

页面重挂载、通知重复点击、设备重启不得重复写入。

## 10.4 日期与时区

- 所有重复时段基于本地墙钟。
- 保存 timezone。
- DST 前后仍保持用户选择的本地时间。
- 日期 key 使用用户本地日期，不用 UTC 截断。
- 跨时区后下一次实例重新计算，历史事件不重写。

# 18. Codex 偏航纠正

如果你准备直接开始 P15-P18，而 P15R SOURCE_GATE 尚未通过：

> 停止新增页面和功能。先完成 P15R：统一 Bottom Sheet、快速添加、快速编辑主次、真正长按拖动、地图标题和全局同类问题审计。P15R SOURCE_GATE 未通过前不得开始后续阶段；RELEASE_GATE 可因无设备保持 PENDING_EXTERNAL。

如果你仍用“移动到哪个象限”弹框代替拖动：

> 普通触摸用户必须长按后直接拖动节点并松手保存。象限选择按钮仅作为无障碍/更多操作替代，不得在普通长按中出现。

如果你保留巨大关闭按钮或底部导航：

> 任务 Sheet 打开时隐藏或完全禁用底部主导航；删除巨大“关闭任务面板”按钮，使用真实可拖动横杆、小型关闭图标、遮罩和系统返回。


如果 Codex 继续往象限页堆内容：

> 停止向象限首屏增加成长、统计、专注历史和设置。象限只负责“现在做什么”。完整成长移到成长页，专注安排移到专注页，全局规则移到我的页面。

如果 Codex 增加第五个页面：

> 不新增“今日 / 自律”主导航。使用现有象限、专注、成长、我的四页，保持用户心理模型稳定。

如果 Codex 只换颜色不改结构：

> 本轮不是单纯换皮。先完成页面唯一职责、唯一主行动、内容归属和状态逻辑，再应用统一 Token 和组件。

如果 Codex 创建第二套日程：

> 专注时段必须与现有 taskExecutionPlan、nextStartAt 和 active focus 通过 FocusAgenda selector 合并。不得出现重复列表、重复提醒或重复 FocusSession。

如果 Codex 开发强阻断：

> 本轮只做提醒与减少干扰。暂停 Accessibility Service、VPN、Device Admin 和无法退出的锁机；这些属于后续平台专项。

如果 Codex 伪造成长趋势：

> 只使用真实 FocusSession、任务快照和 repair record。样本不足就隐藏，不得用当前任务状态伪造历史周趋势。

如果 Codex 再次实现备份合并：

> P14-02B 仍为 BLOCKED_SPEC_GUARD。没有跨任务、步骤、计划、专注、提醒和 Ledger 的完整引用重映射服务时，不得开放合并。

如果 Codex 只输出方案：

> 停止复述规格，直接修改真实源码、迁移、测试和 Android 配置。一次只执行当前阶段，完成后运行门禁并更新进度文件。
